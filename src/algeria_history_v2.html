⚿ Security Architecture
🔐 Layer 1 — XOR-Cipher
Passphrase NSCS-ALGERIA-HISTORY-DB-v3-SECRET-KEY-2025 hashed through FNV-1a → 64-byte rotating key. Zero bytes → 0xAA. Each byte: out[i] = in[i] XOR key[i % 64]. Self-inverse: enc(enc(x)) = x. File wrapped via fmemopen() — parser never sees ciphertext.

🔏 Layer 2 — DJBX33A-64
After every save, a 64-bit hash of the encrypted ciphertext is written to database.txt.sig. Hash on ciphertext — catches content tampering AND key-change attacks. Any single bit flip changes hash completely (avalanche effect). Mismatch → RED ALERT.

⚠ Known Weaknesses
XOR-1 · Single-byte frequency analysis possible if key < plaintext length
XOR-2 · Known-plaintext attack recovers key (XOR is not semantically secure)
HASH-1 · DJBX33A is not cryptographic — collision-resistant but not preimage-resistant
SCOPE · Designed for academic tamper-detection, not production security
